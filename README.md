# SmartRent Backend

한성대 학생이 학교 기자재를 앱에서 찾고 예약하면, 기자재실 관리자가 기기 코드를 찍어 내주고 돌려받는 **기자재 대여 서비스 SmartRent의 백엔드 API 서버**입니다.

> 지금 이 레포에는 **서버 코드가 아직 없고 설계 문서만 있습니다.** 처음이라면 [시작하기](docs/시작하기.md)부터 읽으세요.

> **기능 규칙의 기준본은 이 레포의 [docs/design/기획안.md](docs/design/기획안.md) 하나입니다.** 팀이 쓰던 Word 파일(`SmartRent_서비스기획안_v2.docx`, `SmartRent_서비스기획안.docx`)과 정리 문서(`SmartRent_정리.md`)는 2026-09-28에 옮기기 전의 옛 사본이라 더 고치지 않고, 내용이 다르면 레포의 기획안.md가 맞습니다.

## 주요 기능

기준은 [기획안](docs/design/기획안.md)입니다. 괄호는 기획안 장 번호입니다.

- **가입과 승인**: 학교 메일 인증 → 학생증 제출 → 관리자 승인 뒤 대여 가능, 로그인 5번 실패 시 5분 잠금(1장)
- **내 정보**: 이메일·비밀번호·프로필 사진 변경, 경고 내역, 탈퇴(탈퇴하면 수령 전 예약 자동 취소)(1·7장)
- **기자재 조회**: 목록·검색·상세, 기기 코드로 찾기, 휴대폰이 사진으로 인식한 모델명으로 모델 상세 찾기(2·10장)
- **예약**: 아직 시작하지 않은 시간 칸 여러 개를 한 번에 신청, 동시에 겹치는 대수로 남은 수량 계산, 반출 기자재는 앞뒤 1시간 여유(3장)
- **대여 종류**: 하루 대여, 2일 이상 대여(다음 주 금요일까지), 장기 대여(6개월, 지도교수 승인 메일)(4장)
- **수령·현장 대여·반납**: 관리자가 기기 코드를 찍어 처리, 예약 시작에 내줄 기기가 없으면 경고 없이 즉시 취소(5·6장)
- **연장**: 일반 대여만 한 번(6장)
- **경고와 정지**: 노쇼·연체·파손 경고, 3회면 6개월 정지, 관리자 정정(7장)
- **운영 시간과 휴무일**: 공휴일은 공공데이터에서 자동으로 받고, 관리자는 임시 휴무·공휴일 운영과 운영 시간 변경. 걸리는 예약은 경고 없이 취소(8장)
- **알림**: 반납 전·즉시 반납·예약 취소·노쇼 푸시와 앱 알림함(9장)
- **AI 기자재 추천**: 사용 목적을 쓰면 Gemini가 우리 기자재 중에서 골라 줌(10장)
- **관리자 기능**: 학생 승인·정보 수정, 모델·기기 관리, 공지, 문의·구매 요청 답변, 이용 통계, 관리 기록(11·12장)

**기획안과 앱에 있는 기능은 모두 구현 범위**입니다. 만들지 않는 것은 [기획안 12장](docs/design/기획안.md#12-개발-범위에서-제외한-기능)에 적힌 연체료, 수령·반납 사진, 학생의 반납 신청, 시간 칸 임시 선점, 공간별 권한, 닉네임·학과뿐입니다.

## 기술 스택

원칙: **최신 안정판을 씁니다.** 최신이 아닌 것은 "이유"에 왜 그 버전인지 적습니다. 최신 버전은 2026-09-29에 확인했습니다.

| 구분 | 쓰는 것 | 현재 최신 | 이유 | 상태 |
|---|---|---|---|---|
| 언어 | Java 21 (LTS) | 27(2026-09, LTS 아님), 최신 LTS는 25 | 27은 6개월 뒤 지원이 끝나고 Spring Boot 4.1이 26까지만 지원해 제외. 25 대신 21: 라이브러리·배포 이미지·오류 해결 자료가 가장 많이 쌓인 LTS | 확정 |
| 프레임워크 | Spring Boot 4.1.1 | 4.1.1 | 최신 안정판(B1-01에서 2026-10-01 확인). 4.2는 11월 정식 예정인 시험판(M)이라 쓰지 않음 | 확정 |
| 빌드 | Gradle 9.x (Wrapper) | 9.8.0 | 최신. 따로 설치하지 않고 레포의 Wrapper가 같은 버전을 받음 | 확정 |
| DB | MySQL 9.7 LTS | 9.7 LTS (2026-04) | 최신 LTS. 9.x 중간 버전(Innovation)은 다음 버전이 나오면 지원이 끝나 쓰지 않음 | 확정 |
| ORM | Spring Data JPA | Spring Boot가 맞춘 버전 | 버전을 따로 고르지 않고 Spring Boot 4.1이 서로 맞춰 둔 버전을 씀(검증·보안도 같음) | 확정 |
| 검증 | Bean Validation | Spring Boot가 맞춘 버전 | 요청 값 검사를 어노테이션으로 한 곳에서 | 확정 |
| 인증 | Spring Security + JWT | Spring Boot가 맞춘 버전 | 앱이 쿠키 없이 토큰으로 로그인을 유지. refresh 토큰은 해시로 DB에 저장해 로그아웃·강제 만료 가능 | 확정 |
| API 문서 | springdoc-openapi 3.x (Swagger) | 3.1.1 | 최신. Spring Boot 4는 3.x만 지원 | 확정 |
| 푸시 알림 | Firebase Cloud Messaging (FCM) | 서비스라 버전 없음 | 무료, 안드로이드·iOS 모두 보냄 | 확정 |
| 인증 메일 | Gmail SMTP (개발용) | 서비스라 버전 없음 | 무료, 앱 비밀번호만 있으면 바로 씀. 운영용 메일은 배포 전에 다시 정함 | 확정 |
| AI 추천 | Gemini API 무료 등급 | 모델 ID는 B1-21에서 선정·실제 호출 확인 | 비용 없이 시작. 모델은 무료로 지원되는 것 중 최신으로 | 확정 |
| 공휴일 | 공공데이터포털 한국천문연구원 특일 정보 | 서비스라 버전 없음 | 대체공휴일까지 나오는 공식 출처 | 확정 |
| 서버 | AWS EC2 한 대(MySQL 같이 설치), 사진은 S3 | 서비스라 버전 없음 | 비용: RDS 없이 서버 한 대에 DB까지 둠. 사진은 서버 디스크 대신 S3 | 확정 |
| 테스트 | JUnit 6 | 6.x | 최신. Spring Boot 4가 기본으로 씀 | 확정 |

## 프로젝트 구조 (확정, B1-01)

```
src/main/java/kr/ac/hansung/smartrent/
├── global/
│   ├── config/          # 보안, Swagger, Clock, 스케줄러 설정, 필수 설정 검사
│   ├── security/        # JWT 발급·검증
│   ├── exception/       # 공통 예외, 오류 코드, 전역 예외 처리
│   ├── response/        # 공통 응답 형식
│   └── health/          # 배포 확인용 GET /api/v1/health
└── domain/              # 기능별 controller → service → repository → entity → dto
    ├── auth/            # 가입, 인증 메일, 로그인, 로그인 잠금          (백엔드 1)
    ├── user/            # 내 정보, 학생증, 탈퇴, 관리자 학생 관리      (백엔드 1)
    ├── equipment/       # 모델·기기, 기기 코드, 인식 결과 조회          (백엔드 1)
    ├── operation/       # 운영 시간, 휴무일, 공휴일 받기                (백엔드 1)
    ├── upload/          # 사진 저장(S3·로컬)                           (백엔드 1)
    ├── recommendation/  # AI 추천                                      (백엔드 1)
    ├── board/           # 공지, 문의, 구매 요청                         (백엔드 1)
    ├── statistics/      # 이용 통계, 관리 기록 조회                     (백엔드 1)
    ├── rental/          # 예약, 수령, 현장 대여, 반납, 연장, 정정, 판정 작업 (백엔드 2)
    ├── warning/         # 경고, 정지, 탈퇴 경고 보관                    (백엔드 2)
    └── notification/    # 알림함, 푸시, 알림 설정                       (백엔드 2)
```

## 실행과 시험

```bash
cp .env.example .env     # 값 채우기(시작하기 5절)
docker compose up -d mysql
./gradlew bootRun        # 윈도우: .\gradlew.bat bootRun
./gradlew test           # Docker가 켜져 있어야 함(시험용 MySQL을 따로 띄움)
```

- API 주소: http://localhost:8080/api/v1
- Swagger 화면: http://localhost:8080/swagger-ui/index.html
- 모든 응답: `{ "success": true, "message": "...", "data": { }, "errorCode": null }`. 오류 코드 목록은 [API 명세 1-6절](docs/api/README.md#1-6-오류-형식과-상태-코드).

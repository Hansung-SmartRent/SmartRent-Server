## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| POST | `/api/v1/admin/students/{id}/approve` | 가입 승인 | 관리자 |
| POST | `/api/v1/admin/students/{id}/reject` | 가입 반려 | 관리자 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- 승인 시 [B2-17](B2-17.md)의 재가입 복원 서비스를 호출합니다. 백엔드 2가 복원 서비스를 먼저 제공하고, 백엔드 1이 승인 API 연결 시험을 맡습니다. 복원이 필요한 승인 완료 조건은 서비스 연결 후 충족합니다.

- 승인: `APPROVED`. 반려: 사유와 함께 `REJECTED`.
- 승인·반려와 같은 DB 트랜잭션에서 B1-08의 삭제 작업에 사진 키(`student_id_image_key`)를 남기고 칸을 비웁니다. 커밋 직후 즉시 삭제를 시도하며 실패해도 승인·반려는 유지합니다. B1-08의 파일 삭제 작업이 재시도하며 관리자 `OPERATIONS` 알림을 남깁니다(DB 3절 storage_deletion_jobs).
- 학생에게 `ACCOUNT` 알림, 관리 기록.

## 제외

- 학생증 제출(B1-07)

## 완료 조건

- [ ] 승인·반려 뒤 저장소에 사진이 없다
- [ ] 대기 상태가 아닌 학생은 승인할 수 없다
- [ ] 관리 기록이 남는다
- [ ] 아래 표의 서버 로직·권한·응답·오류는 JUnit 시험으로 확인한다. 실제 메일·푸시·외부 API 연결, OS 명령, 배포·재부팅·백업 복원은 실제 환경 확인으로 구분해 결과를 남긴다. 시험 이름 또는 확인 기록에 이슈 번호와 행 번호·사례 ID를 적는다. 실제 연결을 가짜 응답 시험으로 대체해 완료 처리하지 않는다.
- [ ] PR 양식의 체크리스트를 채웠다

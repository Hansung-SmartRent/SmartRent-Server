## 목적

학기 중 품목 변경과 2일 이상 대여 설정을 관리자가 합니다(기획안 4·11장).

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| GET | `/api/v1/admin/models/{id}` | 관리자용 모델 상세 | 관리자 |
| POST | `/api/v1/admin/models` | 모델 추가 | 관리자 |
| PUT | `/api/v1/admin/models/{id}` | 모델 수정 | 관리자 |
| POST | `/api/v1/admin/models/{id}/archive` | 모델 운영 종료 | 관리자 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- 관리자용 상세(기기 목록 포함), 모델 추가(`source=ADMIN`), 수정(운영 시간 기본값, 간격, 반출 여부, 2일 이상 여부 등).
- 모델 이름 중복 금지: 추가·이름 변경 때 운영 중인 다른 모델과 `name_key`(소문자, 공백 제거)가 같으면 `MODEL_NAME_DUPLICATE`. 운영 종료하면 `name_key`를 비움(DB 설계 3절).
- 운영 종료: 대여 중이면 거절, 앞으로의 예약은 [B2-16](B2-16.md) 서비스로 경고 없이 취소하고 알림.
- 관리 기록.
- 모델 수정에서 `carryOut`, `multiDay`, `maxRentalDays`, `maxRentalMinutes`를 넣고 바꿀 수 있음. 학교 품목의 값은 사이트 원문 기준이므로 바꿀 때 관리 기록에 전·후 값을 남김(기획안 3·4장).

## 연결 작업과 확인 책임

- **백엔드 1(이 이슈):** 모델 운영 종료·운영 시간 기본값 수정 API를 만들고, 저장한 뒤 같은 트랜잭션에서 백엔드 2의 `OperationChangeService`(B2-16)를 호출해 돌려받은 취소·연장 목록을 응답에 넣습니다.
- **백엔드 2:** [B2-16](B2-16.md)에서 서비스와 서비스 단위 시험을 먼저 머지합니다. 이 이슈 PR의 검토자로 들어가 예약 정리 결과가 규칙대로인지 확인합니다.
- **확인 책임:** API를 불렀을 때 사례 결과가 맞는지 확인하는 API 수준 시험은 백엔드 1이 이 이슈에서 씁니다. 예약 정리 규칙 자체의 시험은 백엔드 2가 [B2-16](B2-16.md)에서 씁니다.
- [B2-16](B2-16.md)이 아직 머지 전이면 서비스 이름과 인자만 둘이 먼저 정하고, 이 이슈는 호출 부분을 빼고 진행한 뒤 [B2-16](B2-16.md) 머지 후 붙입니다.

## 완료 조건

- [ ] 운영 종료하면 앞으로의 예약이 취소되고 학생에게 `CANCEL` 알림이 간다
- [ ] 대여 중인 모델은 운영 종료 불가
- [ ] "insta360 evo"처럼 대소문자·공백만 다른 이름으로 모델을 추가하면 `MODEL_NAME_DUPLICATE`, 운영 종료한 모델과 같은 이름은 추가된다
- [ ] 아래 표의 서버 로직·권한·응답·오류는 JUnit 시험으로 확인한다. 실제 메일·푸시·외부 API 연결, OS 명령, 배포·재부팅·백업 복원은 실제 환경 확인으로 구분해 결과를 남긴다. 시험 이름 또는 확인 기록에 이슈 번호와 행 번호·사례 ID를 적는다. 실제 연결을 가짜 응답 시험으로 대체해 완료 처리하지 않는다.
- [ ] PR 양식의 체크리스트를 채웠다

## 서버 구현 후 확인할 것

서버를 만든 뒤 아래 입력을 넣었을 때 예상 결과가 나와야 합니다. 사례 ID가 적힌 행은 [fixtures/cases.json](../../fixtures/cases.json)에 정확한 입력과 결과가 있습니다. 시각 의존 서버 시험은 `Clock`으로 고정합니다. 실제 환경 확인은 실행 시각·환경·결과를 기록합니다.

| # | 입력·상황 | 예상 결과 |
|---|---|---|
| 1 | 모델 추가 | 201, `source` `ADMIN` |
| 2 | 기존 모델과 대소문자·공백만 다른 이름으로 추가 | 409 `MODEL_NAME_DUPLICATE` |
| 3 | 운영 종료한 모델과 같은 이름으로 추가 | 201 |
| 4 | 앞으로의 예약 2건이 있는 모델 운영 종료 | 두 예약 `CANCELLED`, 학생마다 `CANCEL` 알림, 응답에 취소 목록 |
| 5 | 대여 중 기록이 있는 모델 운영 종료 | 409 `MODEL_ARCHIVE_BLOCKED` |
| 6 | 일반 모델을 `multiDay: true`로 수정 | 그 모델의 `GET /models/{id}/availability`에 반납일 선택지가 나옴 |
| 7 | 모델의 `maxRentalMinutes`를 120으로 수정 | 저장되고 관리 기록에 전·후 값, 이후 그 모델 예약에 2시간 제한 적용 |
| 8 | `maxRentalDays`에 0 또는 음수 | 400 `VALIDATION_ERROR` |

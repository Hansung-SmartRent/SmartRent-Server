## 범위

- 빈 운영 MySQL에 B1-02에서 정한 스키마 생성 절차로 두 담당자의 전체 표·제약을 적용한 뒤 `ddl-auto=validate`로 서버를 시작합니다. 가짜 학생·대여 데이터는 넣지 않습니다. 변경 전 백업과 스키마 적용 순서를 README에 적습니다.

- EC2 한 대에 Java 21과 MySQL 9.7 설치, 서버를 서비스(systemd)로 실행.
- S3 버킷(비공개)과 EC2 IAM 역할. 액세스 키를 서버에 두지 않음.
- `.env`는 서버에만. 보안 그룹은 필요한 포트만.
- 매일 `mysqldump` → S3 `backup/`, 수명 주기 규칙으로 오래된 덤프 삭제(확정).
- 사양과 월 예상 비용을 AWS 요금 계산기로 확인해 README 배포 절에 적음.
- 배포 절차를 README 배포 절에 적음.

## 완료 조건

- [ ] 앱이 EC2 주소로 로그인·예약·수령·반납을 한 번 해 봤다
- [ ] 백업 파일이 S3에 생기고 그것으로 복원해 봤다
- [ ] EC2를 다시 켜도 서버가 자동으로 켜진다
- [ ] 아래 표의 서버 로직·권한·응답·오류는 JUnit 시험으로 확인한다. 실제 메일·푸시·외부 API 연결, OS 명령, 배포·재부팅·백업 복원은 실제 환경 확인으로 구분해 결과를 남긴다. 시험 이름 또는 확인 기록에 이슈 번호와 행 번호·사례 ID를 적는다. 실제 연결을 가짜 응답 시험으로 대체해 완료 처리하지 않는다.
- [ ] PR 양식의 체크리스트를 채웠다

## 서버 구현 후 확인할 것

서버를 만든 뒤 아래 입력을 넣었을 때 예상 결과가 나와야 합니다. 사례 ID가 적힌 행은 [fixtures/cases.json](../../fixtures/cases.json)에 정확한 입력과 결과가 있습니다. 시각 의존 서버 시험은 `Clock`으로 고정합니다. 실제 환경 확인은 실행 시각·환경·결과를 기록합니다.

| # | 입력·상황 | 예상 결과 |

| 1 | EC2 주소로 앱에서 로그인·예약·수령·반납 | 모두 성공 |

## 범위

- `docker-compose.yml`(mysql:9.7)과 `spring.datasource` 연결은 B1-01에서 만들었습니다. 이 이슈는 그 위에 표를 만듭니다.

- 운영 DB 최초 생성 방법도 정합니다. `validate`는 표를 만들지 않으므로 버전 관리된 DDL 또는 마이그레이션 중 사용할 방법을 착수 계획에서 확정하고, 빈 MySQL에 적용하는 절차를 시작하기에 적습니다. 이 이슈는 백엔드 1 표와 공통 적용 절차를 맡고, 백엔드 2는 각 표 구현 이슈에서 동일 방식으로 스키마 변경을 제공하며 B1-25가 전체 적용을 확인합니다.

- JPA 설정: 개발은 `ddl-auto=update`(추천), 운영은 `validate`. 표 이름·칸 이름은 DB 설계와 같게(snake_case).
- DB 설계 2절에서 담당이 백엔드 1인 표의 엔티티와 저장소(repository). 단, storage_deletion_jobs는 B1-08에서 같은 스키마 적용 방식으로 추가합니다. `audit_logs`는 공용이므로 여기서 만들고 기록 남기는 서비스 `AuditLogService.record(...)`도 만듭니다.
- 상태 값은 enum + `@Enumerated(EnumType.STRING)`. `equipment_models.source`(SITE/EXAMPLE/ADMIN) 포함.

## 제외

- 대여·경고·알림 표(B2-01, [B2-12](B2-12.md), [B2-13](B2-13.md))
- 처음 데이터 넣기(B1-03)

- [ ] 시작하기 6절을 실제 절차로 고쳤다(맥·윈도우)

## 목적

모델마다 운영 시간을 기본값 또는 특정 날짜만 바꿉니다.

## 참고 명세

- [DB 설계 3절 operating_hours, 4절 운영 시간 변경](../db/README.md)

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| GET | `/api/v1/admin/models/{id}/hours` | 운영 시간 변경 목록 | 관리자 |
| PUT | `/api/v1/admin/models/{id}/hours` | 운영 시간 바꾸기 | 관리자 |
| DELETE | `/api/v1/admin/models/{id}/hours/{date}` | 날짜별 운영 시간 되돌리기 | 관리자 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- 변경 목록 보기, 기본 변경·날짜별 변경, 날짜별 되돌리기.
- 바뀐 시간 밖으로 나가는 예약은 [B2-16](B2-16.md) 서비스로 경고 없이 취소하고 알림, 관리자에게 목록 반환.
- [B2-02](B2-02.md)(칸 만들기)가 이 표를 읽어 그날의 운영 시간을 정함 — 조회 함수 `OperatingHoursService.hoursOn(model, date)`를 만들어 둠(추천).

## 연결 작업과 확인 책임

- **백엔드 1(이 이슈):** 운영 시간 변경 API를 만들고, 저장한 뒤 같은 트랜잭션에서 백엔드 2의 `OperationChangeService`(B2-16)를 호출해 돌려받은 취소·연장 목록을 응답에 넣습니다.
- **백엔드 2:** [B2-16](B2-16.md)에서 서비스와 서비스 단위 시험을 먼저 머지합니다. 이 이슈 PR의 검토자로 들어가 예약 정리 결과가 규칙대로인지 확인합니다.
- **확인 책임:** API를 불렀을 때 사례 결과가 맞는지 확인하는 API 수준 시험은 백엔드 1이 이 이슈에서 씁니다. 예약 정리 규칙 자체의 시험은 백엔드 2가 [B2-16](B2-16.md)에서 씁니다.
- [B2-16](B2-16.md)이 아직 머지 전이면 서비스 이름과 인자만 둘이 먼저 정하고, 이 이슈는 호출 부분을 빼고 진행한 뒤 [B2-16](B2-16.md) 머지 후 붙입니다.

## 서버 구현 후 확인할 것

서버를 만든 뒤 아래 입력을 넣었을 때 예상 결과가 나와야 합니다. 사례 ID가 적힌 행은 [fixtures/cases.json](../../fixtures/cases.json)에 정확한 입력과 결과가 있습니다. 시각 의존 서버 시험은 `Clock`으로 고정합니다. 실제 환경 확인은 실행 시각·환경·결과를 기록합니다.

| # | 입력·상황 | 예상 결과 |
|---|---|---|
| 1 | 09:00~20:00 모델의 기본 운영 시간을 10:00~18:00으로 변경(17:00~19:00 예약과 10:00~11:00 예약이 있음) | 17:00~19:00만 `CANCELLED` + 알림, 응답에 취소 목록 |

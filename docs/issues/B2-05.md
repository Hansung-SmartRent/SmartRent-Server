## 목적

학생·관리자 취소와, 다른 기능(운영 변경, 정지, 탈퇴)이 부를 취소 서비스를 만듭니다.

## 참고 명세

- [기획안 3장 예약](../design/기획안.md)
- [DB 설계 7절 예약 → 취소](../db/README.md)

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| POST | `/api/v1/rentals/{id}/cancel` | 예약 취소 | 학생 |
| POST | `/api/v1/admin/rentals/{id}/cancel` | 관리자 예약 취소 | 관리자 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- 학생: 시작 전 예약만. 관리자: 수령 전 예약 모두.
- `RentalCancelService.cancel(rental, 사유, 경고없음)` 하나로 모아 [B2-10](B2-10.md)·[B2-12](B2-12.md)·[B2-16](B2-16.md)·[B1-09](B1-09.md)가 호출.
- `CANCEL` 알림(B2-13), 관리자 취소는 관리 기록.

## 제외

- 운영 변경 때 어떤 예약을 고를지(B2-16)

## 완료 조건

- [ ] 시작 뒤의 예약은 학생이 취소할 수 없다
- [ ] 취소하면 대수가 돌아온다
- [ ] 취소 알림이 생긴다
- [ ] 아래 표의 서버 로직·권한·응답·오류는 JUnit 시험으로 확인한다. 실제 메일·푸시·외부 API 연결, OS 명령, 배포·재부팅·백업 복원은 실제 환경 확인으로 구분해 결과를 남긴다. 시험 이름 또는 확인 기록에 이슈 번호와 행 번호·사례 ID를 적는다. 실제 연결을 가짜 응답 시험으로 대체해 완료 처리하지 않는다.
- [ ] PR 양식의 체크리스트를 채웠다

## 서버 구현 후 확인할 것

서버를 만든 뒤 아래 입력을 넣었을 때 예상 결과가 나와야 합니다. 사례 ID가 적힌 행은 [fixtures/cases.json](../../fixtures/cases.json)에 정확한 입력과 결과가 있습니다. 시각 의존 서버 시험은 `Clock`으로 고정합니다. 실제 환경 확인은 실행 시각·환경·결과를 기록합니다.

| # | 입력·상황 | 예상 결과 |
|---|---|---|
| 1 | 시작 전 `RESERVED` 예약을 학생이 취소 | `CANCELLED`, `CANCEL` 알림, 그 칸 남은 대수 +1 |
| 2 | 시작 시각이 지난 `RESERVED` 예약 취소 | 409 `NOT_CANCELLABLE` |

| 4 | 관리자 취소 | `CANCELLED`, 관리 기록 1건 |

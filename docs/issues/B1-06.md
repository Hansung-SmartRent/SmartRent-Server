## 목적

마이페이지에서 보는 정보와 이메일·비밀번호 변경을 만듭니다(기획안 1장). 프로필 사진 변경은 B1-08.

## 참고 명세

- [기획안 1장 계정](../design/기획안.md)
- [openapi.yaml](../api/openapi.yaml) 내 정보 묶음

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| GET | `/api/v1/users/me` | 내 정보 | 로그인한 사용자 |
| PUT | `/api/v1/users/me/password` | 비밀번호 변경 | 로그인한 사용자 |
| PUT | `/api/v1/users/me/email` | 이메일 변경 | 로그인한 사용자 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- `GET /users/me`: 이름, 학번, 이메일, 승인 상태, 정지 정보, 유효 경고 수(경고 수는 [B2-12](B2-12.md) 서비스를 호출, 그 전에는 0으로 두고 주석).
- 비밀번호 변경: 현재 이메일로 받은 인증번호(`PASSWORD_RESET` 목적)로 확인한 뒤 바꿈(기획안 1장). 바꾸면 그 사용자의 리프레시 토큰을 모두 지움.
- 이메일 변경: 새 학교 메일로 인증번호(`EMAIL_CHANGE`) 확인 뒤 변경.

## 제외

- 프로필 사진(B1-08)
- 학생증(B1-07)
- 탈퇴(B1-09)

## 완료 조건

- [ ] openapi.yaml의 세 API가 명세대로 응답한다
- [ ] 현재 이메일의 인증번호가 틀리거나 만료되면 거절된다. 현재 비밀번호는 요청받지 않는다
- [ ] 이미 쓰는 이메일로는 바꿀 수 없다
- [ ] 아래 표의 서버 로직·권한·응답·오류는 JUnit 시험으로 확인한다. 실제 메일·푸시·외부 API 연결, OS 명령, 배포·재부팅·백업 복원은 실제 환경 확인으로 구분해 결과를 남긴다. 시험 이름 또는 확인 기록에 이슈 번호와 행 번호·사례 ID를 적는다. 실제 연결을 가짜 응답 시험으로 대체해 완료 처리하지 않는다.
- [ ] PR 양식의 체크리스트를 채웠다

## 목적

학생이 낸 학생증 사진(실물 학생증 사진이나 헤이영 전자학생증 캡처)에서 확인할 부분만 잘라 줍니다. 학생은 제출 전에 잘린 결과에 얼굴·이름·학번이 제대로 나오는지 미리 보고, 관리자는 같은 칸에서 바로 확인합니다.

흐름: 촬영·사진 선택 → 서버 자동 자르기 → 결과 미리 보기 → 학생이 확인 후 제출 (잘못 잘렸으면 원본으로 제출하거나 다시 촬영·선택)

## 만들 API

요청·응답 칸은 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| POST | `/api/v1/auth/student-id-preview` | 고른 사진을 잘라 돌려줌. 저장하지 않음 | 없음(가입 인증번호) 또는 학생 |
| POST | `/api/v1/users/me/student-id` | (바뀜) `useCrop`에 따라 다시 잘라 원본과 함께 저장 | 학생 |
| GET | `/api/v1/admin/students/{id}` | (바뀜) 응답에 `studentIdCropUrl`(잘린 사진) 추가. `studentIdImageUrl`은 원본 | 관리자 |

## 범위

- **자르기**: 사진에서 필요한 영역을 찾아 자릅니다.
  - 실물 학생증 사진: 카드 테두리 안쪽
  - 헤이영 캡처: 학교명·이름·학번·얼굴이 있는 윗부분. 아래 QR 부분은 넣지 않음
  - 피그마 예시 배치와 똑같은지가 아니라, 필요한 영역을 찾았는지를 봅니다. 휴대폰 크기나 헤이영 업데이트로 배치가 조금 달라져도 동작해야 합니다.
- **미리 보기 API**: 잘린 사진(JPEG, base64)을 돌려줍니다. 못 찾으면 `cropped=false`, `image=null`.
  - 가입 중(로그인 전): email과 그 이메일의 가입 인증번호를 같이 받아 확인합니다(맞고, 5분 안, 아직 안 씀). 인증번호는 소모하지 않습니다. 틀리면 `OTP_INVALID`, 지났으면 `OTP_EXPIRED`.
  - 재제출: 로그인한 학생 토큰으로 부릅니다.
  - **임시 이미지 처리**: 사진을 저장소·DB·로그 어디에도 남기지 않습니다. 요청을 처리하는 동안 메모리에서만 다루고 응답 뒤 버립니다.
- **최종 제출**: `useCrop=true`(기본)이면 같은 방법으로 다시 잘라 [B1-08](B1-08.md)의 저장 기능으로 `student-id/`에 저장하고 `users.student_id_crop_key`에 남깁니다. 못 찾으면 원본만 저장합니다. `useCrop=false`(학생이 "원본으로 제출")이면 원본만 저장합니다.
- 학생 상세 조회에서 잘린 사진과 원본의 임시 주소를 함께 줍니다. 두 주소는 관리자만 받습니다.
- 승인·반려 때 [B1-15](B1-15.md)가 원본과 잘린 사진 키를 둘 다 삭제 작업에 남기고 지우도록 맞춥니다.
- 사진은 서버 안에서만 처리하고 외부 서비스로 보내지 않습니다.

## 제외

- 기울어진 사진을 반듯하게 펴는 보정(별도 검토)
- 사진에서 글자를 읽어 이름·학번이 맞는지 자동 검사하는 기능(기획안에 없음)
- QR 인식·검사
- 앱 화면 구현(업로드 칸의 미리 보기 표시, "원본으로 제출"·"다시 고르기" 버튼)은 앱 작업

## 완료 조건

- [ ] 헤이영 캡처와 실물 학생증 사진에서 각각 필요한 영역이 잘린다
- [ ] 미리 보기 API가 잘린 사진을 돌려주고, 사진이 저장소·DB·로그에 남지 않는다
- [ ] 영역을 못 찾으면 미리 보기는 `cropped=false`, 제출은 원본만 남고 성공한다
- [ ] `useCrop=false`로 내면 원본만 저장된다
- [ ] 학생 상세 조회가 두 주소를 주고, 관리자가 아니면 받을 수 없다
- [ ] 승인·반려 뒤 원본과 잘린 사진이 모두 저장소에 없다
- [ ] 시험용 사진은 실제 학생 사진이 아닌 가상 예시로 만든다
- [ ] 아래 표의 서버 로직·권한·응답·오류는 JUnit 시험으로 확인한다. 실제 메일·푸시·외부 API 연결, OS 명령, 배포·재부팅·백업 복원은 실제 환경 확인으로 구분해 결과를 남긴다. 시험 이름 또는 확인 기록에 이슈 번호와 행 번호·사례 ID를 적는다. 실제 연결을 가짜 응답 시험으로 대체해 완료 처리하지 않는다.
- [ ] PR 양식의 체크리스트를 채웠다

## 미정 사항 (누가, 언제)

- 이미지 처리 도구: OpenCV가 후보. 백엔드 1이 착수 계획 때 가상으로 만든 헤이영 캡처와 실물 학생증 사진으로 영역을 찾는지 시험한 뒤 정합니다(실제 학생 사진은 쓰지 않음).
- 미리 보기 API 호출 횟수 제한을 둘지: 백엔드 1이 착수 계획 때 정합니다(인증번호가 5분 뒤 만료되어 가입 중 호출은 이미 제한됨).
- 기울기 보정을 넣을지: 팀이 이 이슈를 끝낸 뒤 실제 사진으로 결과를 보고 정합니다.

## 목적

가입 뒤 이름·학번과 학생증 사진을 내고 관리자 승인을 기다리게 합니다.

## 참고 명세

- [기획안 1장 계정](../design/기획안.md)
- [DB 설계 3절 users, 4절 삭제와 보존](../db/README.md)
- [외부 연결 5절 S3](../외부연결.md)

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| POST | `/api/v1/users/me/student-id` | 학생증 제출·재제출 | 학생 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- 사진은 실물 학생증 사진이나 헤이영 전자학생증의 QR 화면 캡처를 받습니다. QR은 검사하지 않습니다(기획안 1장).
- 이름·학번·사진을 받아 사진은 [B1-08](B1-08.md)의 저장 기능으로 `student-id/`에 저장, 승인 상태 `PENDING`.
- 같은 학번의 다른 계정이 있으면 거절(오류 코드는 openapi.yaml).
- 반려 뒤 재제출 가능. 옛 사진은 이미 지워져 있음(B1-15).
- 관리자에게 알림(`ACCOUNT` 또는 명세의 종류) — [B2-13](B2-13.md) 서비스 호출.

## 제외

- 승인·반려(B1-15)
- 사진에서 필요한 부분을 잘라 저장하는 자동 자르기([B1-26](B1-26.md)). 이 이슈에서는 원본만 저장합니다.

## 완료 조건

- [ ] 제출하면 `PENDING`, 사진이 저장소에 있다
- [ ] 중복 학번 거절
- [ ] 재제출 가능
- [ ] 아래 표의 서버 로직·권한·응답·오류는 JUnit 시험으로 확인한다. 실제 메일·푸시·외부 API 연결, OS 명령, 배포·재부팅·백업 복원은 실제 환경 확인으로 구분해 결과를 남긴다. 시험 이름 또는 확인 기록에 이슈 번호와 행 번호·사례 ID를 적는다. 실제 연결을 가짜 응답 시험으로 대체해 완료 처리하지 않는다.
- [ ] PR 양식의 체크리스트를 채웠다

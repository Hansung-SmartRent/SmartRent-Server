## 목적

학교 메일로만 가입하게 하고, 인증번호를 메일로 보냅니다.

## 참고 명세

- 확인 사례: `AUTH-01` 학교 이메일은 @ 뒤 전체가 정확히 같아야 한다, `AUTH-02` 인증번호는 5분 동안만 유효하고, 만료와 틀림을 구분한다 ([fixtures/cases.json](../../fixtures/cases.json))

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| POST | `/api/v1/auth/email-codes` | 인증번호 보내기 | 없음 |
| POST | `/api/v1/auth/signup` | 회원가입 | 없음 |
| POST | `/api/v1/auth/password/reset` | 비밀번호 찾기 | 없음 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- 인증번호 6자리를 해시로 저장, 5분 유효, 재발송하면 옛 번호 무효.
- 이메일은 소문자로 바꿔 @ 뒤 전체가 허용 도메인과 정확히 같은지 비교.
- 가입: 이메일·인증번호·비밀번호. 가입 직후 승인 상태 `NONE`(학생증 미제출).
- 재가입한 학번에 보관된 경고가 있으면 되살림 — [B2-17](B2-17.md)의 서비스를 호출(학번은 학생증 제출 때 들어오므로 실제 호출 시점은 [B1-07](B1-07.md)과 함께 정함).
- 비밀번호 찾기: 인증번호 확인 후 새 비밀번호 설정.
- `MAIL_ENABLED=false`면 로그에 번호를 찍는 개발용 대체(local에서만).

## 서버 구현 후 확인할 것

서버를 만든 뒤 아래 입력을 넣었을 때 예상 결과가 나와야 합니다. 사례 ID가 적힌 행은 [fixtures/cases.json](../../fixtures/cases.json)에 정확한 입력과 결과가 있습니다. 시각 의존 서버 시험은 `Clock`으로 고정합니다. 실제 환경 확인은 실행 시각·환경·결과를 기록합니다.

| # | 입력·상황 | 예상 결과 |
|---|---|---|
| 1 | 사례 AUTH-01 입력 | 사례의 예상 결과(허용 4개, 거절 3개는 `EMAIL_DOMAIN_NOT_ALLOWED`, `@hansung.ac.kr`는 `VALIDATION_ERROR`) |
| 2 | 사례 AUTH-02 입력 | 10:04:59 성공, 10:05:01 `OTP_EXPIRED`, 틀린 번호 `OTP_INVALID` |
| 3 | newstudent@hansung.ac.kr가 아닌 새 주소로 인증번호 받고 가입 | users에 approval `NONE`, email 소문자로 저장 |
| 4 | 이미 가입된 김하늘(demo@hansung.ac.kr) 주소로 SIGNUP 인증번호 요청 | 409 `EMAIL_ALREADY_USED` |
| 5 | 인증번호를 두 번 받고 첫 번호로 가입 | 400 `OTP_INVALID` |
| 6 | 메일 보내기가 실패하도록 한 시험 | 503 `MAIL_UNAVAILABLE`, 그 번호로 가입하면 `OTP_INVALID` |
| 7 | 김하늘(demo@hansung.ac.kr) 비밀번호 찾기(PASSWORD_RESET 번호 + 새 비밀번호) | 새 비밀번호로 로그인 200, 옛 비밀번호는 401 |

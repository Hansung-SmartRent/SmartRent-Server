## 목적

관리자가 기기 코드를 찍고 상태를 골라 반납을 승인합니다.

## 참고 명세

- [기획안 6장 반납과 연장](../design/기획안.md)
- [기획안 7장 경고와 정지](../design/기획안.md)
- [DB 설계 7절 대여 중 → 반납, 경고와 정지](../db/README.md)
- 확인 사례: `RET-01` 기한이 지나면 판정 작업이 연체 경고 1회, 늦게 반납해도 다시 붙이지 않는다, `RET-02` 대여 중 스스로 신고한 파손은 경고 없음, 신고 없이 파손 반납이면 경고 1회 ([fixtures/cases.json](../../fixtures/cases.json))

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| GET | `/api/v1/admin/returns/lookup` | 반납할 대여 찾기 | 관리자 |
| POST | `/api/v1/admin/rentals/{id}/return` | 반납 처리 | 관리자 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- 기기를 `DAMAGED`로 바꾸는 처리에도 [B2-16](B2-16.md)의 예약 정리 서비스를 같은 트랜잭션에서 호출합니다. 이미 점검 중으로 빠진 기기를 파손으로 바꿀 때는 수량을 이중 차감하지 않고 현재 상태로 다시 계산합니다. 연결 시험은 이 이슈 담당 백엔드 2가 맡습니다.

- 반납할 대여 찾기(기기 코드로).
- 반납 시각 = 승인 시각. 늦으면 `LATE` 경고(이미 있으면 안 붙임).
- `DAMAGED`이고 학생 신고(B1-13)가 없었으면 `DAMAGE` 경고. 기기 상태를 고른 값으로.
- 정지 대기 학생이 마지막 기기를 반납하면 6개월 정지 시작(B2-12).
- 이미 예약 시작 시 기기 부족으로 취소된 예약은 반납돼도 복원하거나 수령 안내를 보내지 않습니다. 반납 요청 전에 미처리된 시작 판정이 있으면 시작 시점 기준으로 먼저 처리합니다(B2-10).
- `RETURN` 알림, 관리 기록.

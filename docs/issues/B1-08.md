## 목적

학생증·프로필·모델 사진을 한 가지 방법으로 저장하고 지웁니다.

## 참고 명세

- [외부 연결 5절 S3](../외부연결.md)
- [DB 설계 3절 users·model_images](../db/README.md)
- [기획안 1장 계정(프로필 사진)](../design/기획안.md)

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| PUT | `/api/v1/users/me/profile-image` | 프로필 사진 바꾸기 | 로그인한 사용자 |
| DELETE | `/api/v1/users/me/profile-image` | 프로필 사진 지우기 | 로그인한 사용자 |
| POST | `/api/v1/admin/models/{id}/images` | 모델 사진 올리기 | 관리자 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- DB 3절 `storage_deletion_jobs`의 삭제 작업 저장·즉시 실행·실패 재시도를 만듭니다. B1-15와 프로필 사진 교체가 이 서비스를 호출합니다. 재시도 간격은 1분(확정). 대여 판정 작업(B2-10)과 소유 책임을 분리합니다.

- `StorageService`(올리기, 지우기, 임시 주소 만들기) 하나에 `local`/`s3` 구현 두 개. `STORAGE_MODE`로 고름.
- 형식 jpg·png, 10MB 이하(확정), 어기면 `400 FILE_INVALID`. 올리기 실패는 `503 STORAGE_UNAVAILABLE`이고 DB는 바꾸지 않음.
- 버킷은 비공개, 앱에는 10분짜리 임시 주소(확정).
- 프로필 사진 바꾸기·지우기(기획안 1장). 바꾸면 옛 사진 삭제.
- 관리자 모델 사진 올리기(1~3장).

## 제외

- 학생증 제출 흐름(B1-07)
- 실제 S3 버킷 만들기(B1-25에서 함께 해도 됨)

## 완료 조건

- [ ] local 모드에서 올리기·지우기·임시 주소가 시험으로 확인된다
- [ ] 실제 S3에 한 번 올리고 버킷 주소로 직접 열면 거부된다(키가 있는 사람이 확인)
- [ ] 10MB 넘는 파일·gif는 `FILE_INVALID`
- [ ] 아래 표의 서버 로직·권한·응답·오류는 JUnit 시험으로 확인한다. 실제 메일·푸시·외부 API 연결, OS 명령, 배포·재부팅·백업 복원은 실제 환경 확인으로 구분해 결과를 남긴다. 시험 이름 또는 확인 기록에 이슈 번호와 행 번호·사례 ID를 적는다. 실제 연결을 가짜 응답 시험으로 대체해 완료 처리하지 않는다.
- [ ] PR 양식의 체크리스트를 채웠다

## 만들 API

| 방법 | 주소 | 하는 일 | 권한 |
|---|---|---|---|
| PUT | `/api/v1/users/me/push-token` | 푸시 토큰 등록 | 로그인한 사용자 |
| GET | `/api/v1/notifications` | 알림함 | 로그인한 사용자 |
| POST | `/api/v1/notifications/{id}/read` | 알림 읽음 | 로그인한 사용자 |
| POST | `/api/v1/notifications/read-all` | 모두 읽음 | 로그인한 사용자 |

요청·응답 칸과 오류 코드는 [openapi.yaml](../api/openapi.yaml)의 같은 주소를 봅니다.

## 범위

- 알림 연결은 relatedType + relatedId 쌍을 사용합니다. 문의·구매 답변은 RESPONSE이며 INQUIRY/PURCHASE_REQUEST로 나눕니다. DB 3·8절 기준으로 모든 호출부와 FCM 데이터에 같은 연결 정보를 전달합니다. 연결 없는 알림은 둘 다 null입니다.

- `NotificationService.notify(user, kind, title, body, relatedType, relatedId)` 하나로 모음(추천). 관리자 전체에게 보내는 함수도.
- 알림함 목록·읽음·모두 읽음, 푸시 토큰 등록.
- 로그아웃 때 그 휴대폰 푸시 토큰 지우기: `global/port/PushTokenRemover`를 구현한 빈을 만들고, 그때까지 아무것도 안 하던 `NoPushTokensYet`을 지웁니다(B1-04 확인 11행의 푸시 토큰 부분).
- FCM 발송: 실패해도 알림함은 남김, `UNREGISTERED` 토큰 삭제, 재시도 없음(확정). `FCM_ENABLED=false`면 알림함만.
- 끌 수 있는 알림(`DUE`)이 꺼져 있으면 푸시 안 보냄(설정은 [B2-14](B2-14.md)).
- **다른 이슈가 일찍 알림을 부를 수 있게, 알림함 저장만 하는 부분을 먼저 머지해도 됩니다.**

# 외부 서비스 연결

서버가 우리 코드 밖의 서비스와 이어지는 다섯 곳입니다. 각 서비스마다 **준비물 → 환경변수 → 연결 방법 → 실패하면 → 완료 기준** 순서로 적었습니다.

- 비밀값(비밀번호, API 키, 키 파일)은 **절대 레포에 올리지 않습니다.** `.env`(레포에 안 올라감)에 넣고, 칸 이름만 [.env.example](../.env.example)에 적습니다. 자세한 규칙은 [시작하기 9절](시작하기.md#9-비밀정보와-올리면-안-되는-파일).
- 아래 명령이나 설정 이름은 각 서비스의 공식 문서로 한 번 더 확인하고 쓰세요. 이 문서는 서버 코드가 생기기 전에 쓴 것이라 실제로 실행해 확인하지 않았습니다.
- 개발 중에는 외부 서비스 없이도 서버가 켜지게 만듭니다(각 절의 "개발용 대체"). 팀원 모두가 키를 가질 필요가 없게 하기 위해서입니다.

| 서비스 | 쓰는 곳 | 담당 | 이슈 |
|---|---|---|---|
| 1. Gmail SMTP | 이메일 인증번호 | 백엔드 1 | B1-05 |
| 2. Firebase Cloud Messaging(FCM) | 휴대폰 푸시 알림 | 백엔드 2 | B2-13 |

| 4. 공공데이터포털 특일 정보 | 공휴일 받기 | 백엔드 1 | B1-19 |
| 5. AWS S3 | 학생증·프로필·모델 사진 | 백엔드 1 | B1-08 |

## 1. 인증 메일 — Gmail SMTP (개발용, 확정)

- **준비물:** 팀 공용 Gmail 계정 하나. 그 계정에 **2단계 인증을 켜고 "앱 비밀번호"를 발급**할 수 있는지 먼저 확인합니다. 학교 계정이나 회사 관리 계정은 앱 비밀번호가 막혀 있을 수 있습니다.
- **환경변수:** `MAIL_HOST=smtp.gmail.com`, `MAIL_PORT=587`, `MAIL_USERNAME=팀계정@gmail.com`, `MAIL_PASSWORD=앱 비밀번호 16자리`, `MAIL_ENABLED=true`
- **연결 방법:** Spring의 메일 스타터(`spring-boot-starter-mail`)로 보냅니다. 제목 "[SmartRent] 인증번호", 본문에 6자리 번호와 "5분 안에 입력" 안내.
- **개발용 대체:** `MAIL_ENABLED=false`면 메일을 보내지 않고 서버 로그에 인증번호를 찍습니다(개발 설정에서만). 이 기능이 운영 설정에서 켜지지 않게 막습니다.
- **실패하면:**
  - 보내기에 실패하면 방금 만든 인증번호를 무효로 하고 `503 MAIL_UNAVAILABLE`을 돌려줍니다. 학생은 "다시 받기"를 누르면 됩니다.
  - Gmail 개인 계정은 하루 발송 한도가 있습니다(정확한 수치는 Google 도움말 확인). 시연 전에 여러 번 가입 시험을 하면 한도에 걸릴 수 있습니다.
- **완료 기준:** 실제 학교 메일 주소 하나(팀원 본인)로 가입 인증번호를 받아 5분 안에 가입이 되고, 5분이 지나면 `OTP_EXPIRED`가 나옵니다.

## 2. 푸시 알림 — FCM

- **준비물:** Firebase 프로젝트(팀 계정으로 만듦), 안드로이드·iOS 앱 등록, **서비스 계정 키 JSON 파일**.
- **환경변수:** `FCM_CREDENTIALS_PATH=/서버 안 경로/firebase-key.json`, `FCM_ENABLED=true`. 키 파일은 레포 밖에 둡니다.
- **연결 방법:** Firebase Admin SDK(Java)로 보냅니다. 앱이 `PUT /users/me/push-token`으로 보낸 토큰에 제목·본문·`kind`·`relatedId`를 담아 보냅니다.
- **앱 쪽 확인 필요:** 지금 앱은 Expo로 만들었습니다. 서버가 FCM으로 직접 보내려면 앱이 기기의 FCM 토큰을 받아 와야 하고, Expo Go가 아닌 개발 빌드가 필요할 수 있습니다. 프론트 담당과 방식을 먼저 정합니다(이슈 B2-13 미정 사항).
- **개발용 대체:** `FCM_ENABLED=false`면 푸시는 보내지 않고 알림함 기록(`notifications` 표)만 남깁니다.
- **실패하면:**
  - 푸시가 실패해도 **알림함 기록은 항상 남깁니다.** 학생은 앱을 열면 알림함에서 봅니다.
  - FCM이 "없는 토큰(UNREGISTERED)"이라고 답하면 그 토큰을 지웁니다.
  - 그 밖의 실패는 로그만 남기고 다시 보내지 않습니다(확정). 판정 작업이 같은 알림을 두 번 만들지 않게 `due_notified` 같은 표시를 먼저 저장합니다.
- **완료 기준:** 팀원 휴대폰 한 대에서 "반납 15분 전" 알림을 받습니다. 알림 설정을 끄면 반납 전 알림은 오지 않고 알림함에만 남습니다.

## 3. AI 추천 — Gemini API

- **준비물:** Google AI Studio에서 발급한 Gemini API 키와 무료 등급을 사용할 수 있는 프로젝트. 유료 등급 전환·결제 연결은 별도 승인 없이 하지 않습니다.
- **모델:** 제공자는 Gemini로 확정했습니다. 구체적인 모델 ID는 B1-21에서 해당 프로젝트의 무료 지원 모델·한도를 확인해 선정하고 실제 호출로 검증합니다. 임의 ID를 예제에 넣지 않으며 확인 전에는 "모델 ID 검증 전"입니다.
- **환경변수:** `GEMINI_API_KEY=...`, `AI_MODEL_ID=확인한 모델 ID`, `AI_ENABLED=true`. `.env.example`의 키와 모델 ID는 비워 둡니다. 활성화할 때 두 값은 필수입니다.
- **연결 방법:** Google의 Gemini API 공식 Java SDK 또는 REST API. 구현 시 [공식 시작 안내](https://ai.google.dev/gemini-api/docs/quickstart)의 지원 방식과 버전을 확인합니다. Spring이 `.env`에서 읽은 키·모델 ID를 클라이언트에 명시적으로 전달하며 SDK가 OS 환경변수에서 자동으로 읽는다고 가정하지 않습니다.
  1. 요청에 **우리 모델 목록**(id, 이름, 카테고리, 활용 방안, 장기 여부)과 학생의 사용 목적을 넣습니다.
  2. 답은 JSON으로 받도록 지시합니다: `{"items":[{"modelId":48,"reason":"..."}]}`
  3. 서버가 받은 `modelId`가 실제로 있는지 확인하고, 없는 것은 버립니다.
  4. 대여 가능 여부는 넣지 않습니다(기획안 10장).
  5. 요청·결과를 `recommendation_logs`에 남깁니다.
- **개발용 대체:** `AI_ENABLED=false`면 모델 이름에 사용 목적의 단어가 들어간 모델 3개를 돌려주는 간단한 대체 추천을 씁니다. 대체 추천임을 로그에 남깁니다.
- **실패하면:** 시간 초과(20초), 키 오류, 한도 초과, JSON이 아닌 답은 모두 `503 AI_UNAVAILABLE`. 앱은 "잠시 뒤 다시 시도" 안내를 보여 줍니다. 자동으로 여러 번 다시 부르지 않습니다(비용).
- **비용·한도:** 서비스 자체의 사용자별 횟수 제한은 두지 않지만, Google의 모델·프로젝트별 무료 요청·토큰 한도는 적용됩니다. 한도 초과는 `503 AI_UNAVAILABLE`로 처리하며 유료 모델로 자동 전환하지 않습니다. B1-21에서 확인한 모델 ID·무료 등급·한도·확인 날짜를 기록합니다. [공식 요금](https://ai.google.dev/gemini-api/docs/pricing), [한도](https://ai.google.dev/gemini-api/docs/rate-limits)를 확인합니다.
- **전송 범위:** 무료 등급의 입력·응답은 제품 개선에 사용될 수 있습니다. 기자재 정보와 추천에 필요한 사용 목적만 보내고, 계정 이름·학번·이메일·학생증·대여 이력은 요청에 포함하지 않습니다. 자유 입력에도 개인정보를 쓰지 않도록 안내합니다.
- **완료 기준:** 실제 호출로 모델 ID를 확인했고, "동아리 행사 영상을 360도로 찍고 싶어요"를 넣으면 우리 목록에 있는 모델(예: Insta360 EVO)과 이유가 옵니다.

## 4. 공휴일 — 공공데이터포털 특일 정보

- **준비물:** 공공데이터포털(data.go.kr)에서 "한국천문연구원 특일 정보" 활용 신청 후 받은 서비스 키. 공휴일 조회 기능(공휴일 정보 조회)을 씁니다. 정확한 주소와 요청 칸은 포털의 활용 가이드로 확인합니다.
- **환경변수:** `HOLIDAY_API_KEY=...`, `HOLIDAY_SYNC_ENABLED=true`
- **연결 방법:**
  - 매일 한 번(새벽 4시) 올해와 내년 공휴일을 받습니다.
  - `holidays` 표에 `source=PUBLIC`으로 넣거나 이름을 고칩니다. 관리자가 넣은 임시 휴무(`source=ADMIN`)와 공휴일 운영 표시(`open_override`)는 건드리지 않습니다.
  - 공휴일이 새로 생겨 걸리는 예약이 있으면 임시 휴무와 같은 방식으로 취소하고 알립니다.
- **개발용 대체:** [fixtures/holidays.json](../fixtures/holidays.json)(2026·2027년)을 처음 데이터로 넣습니다.
- **실패하면:** 이미 저장한 달력을 그대로 쓰고, 관리자에게 알림(`kind=OPERATIONS`)과 로그를 남깁니다([기획안 8장](design/기획안.md#8-운영-시간과-휴무)). 다음 날 다시 시도합니다.
- **완료 기준:** 서비스 키로 2027년 공휴일을 받아 `holidays` 표가 채워지고, 키를 일부러 틀리게 넣으면 기존 달력이 유지되며 관리자 알림이 생깁니다.

## 5. 사진 저장 — AWS S3

- **준비물:** S3 버킷 하나(공개 접근 차단), EC2에 붙일 IAM 역할(그 버킷만 읽고 쓰는 권한).
- **환경변수:** `STORAGE_MODE=s3`(개발은 `local`), `S3_BUCKET=smartrent-...`, `AWS_REGION=ap-northeast-2`. EC2에서는 IAM 역할을 쓰므로 액세스 키를 환경변수에 넣지 않습니다(확정). 개인 컴퓨터에서 S3를 시험할 때만 AWS CLI 로그인 정보를 씁니다.
- **연결 방법:**
  - 폴더(접두어)를 나눕니다: `student-id/`, `profile/`, `model/`
  - 버킷은 공개하지 않고, 앱에는 **10분짜리 임시 주소(presigned URL)**를 줍니다(확정).
  - 학생증 사진은 원본과 서버가 잘라 만든 사진을 `student-id/`에 함께 두고, 승인·반려하면 둘 다 바로 지웁니다(기획안 1장). 프로필 사진을 바꾸면 옛 사진을 지웁니다.
  - 학생증 자동 자르기(B1-26)는 서버 안에서 이미지를 처리하며 외부 서비스로 사진을 보내지 않습니다. 제출 전 미리 보기 사진은 S3·로컬 폴더 어디에도 저장하지 않습니다. 도구는 OpenCV가 후보이고, B1-26 착수 때 실제 학생증 사진과 헤이영 캡처로 영역을 찾는지 시험한 뒤 정합니다.
  - 형식은 jpg·png, 크기는 10MB 이하(확정). 어기면 `400 FILE_INVALID`.
- **개발용 대체:** `STORAGE_MODE=local`이면 프로젝트 밖의 로컬 폴더(예: `~/smartrent-uploads`)에 저장합니다.
- **실패하면:** 올리기에 실패하면 `503 STORAGE_UNAVAILABLE`로 알리고 DB에는 아무것도 바꾸지 않습니다. 삭제할 키는 DB `storage_deletion_jobs`에 먼저 남기고 커밋 직후 삭제합니다. 실패해도 승인·반려 결과는 유지하고 B1-08의 파일 삭제 작업이 재시도합니다. 성공하면 작업 행을 지우며 재시작 후에도 남은 대상을 처리합니다(DB 3절).
- **완료 기준:** 학생증을 올리고 관리자가 승인하면 S3에서 그 파일이 사라집니다. 버킷 주소로 직접 열면 거부됩니다.

## 6. 배포 — AWS EC2 (참고)

서버 배포는 이번 문서 작업 범위가 아니지만, 위 연결들이 어디서 도는지 알 수 있게 정한 것만 적습니다.

- EC2 한 대에 Spring Boot 서버와 MySQL 9.7을 함께 설치합니다. RDS는 쓰지 않습니다(확정). 사진은 S3에 둡니다(5절).
- 사양은 신규 계정 크레딧 안에서 버틸 수 있는 작은 사양을 씁니다(확정). 정확한 월 비용은 배포 이슈(B1-25)에서 AWS 요금 계산기로 확인해 적습니다.
- DB는 직접 백업해야 합니다. 매일 `mysqldump`로 덤프를 만들어 S3의 `backup/` 폴더에 올리고, 오래된 덤프는 S3 수명 주기 규칙으로 지웁니다(확정).
